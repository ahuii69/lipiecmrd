## 1. Stan przed

Runtime V2 działał (cienka fasada `chat_runtime.py`, pakiet `aihub/turn/*`, idempotency, locks, tools, write-back). Brakowało jednak warstwy **rozumienia pragmatyki rozmowy** przed strategią.

Skutki:

- krótkie zaczepki typu „Lody robisz?” szły w literalny deser,
- `short + self-contained ≈ instant` przecinało historię przy elipsie/ironii,
- „przed wczoraj” i sport lądowały w web jako surowy złamany string,
- sarkazm bywał chwalony („dzięki”),
- brak response critic na złe znaczenie.

## 2. Root causes

1. Brak kanonicznej analizy pragmatycznej przed `select_strategy`.
2. Heurystyka długości wiadomości traktowała short jako easy.
3. Freshness guardrail (`wczoraj` ⊂ `wczorajszy`) **ponownie wymuszał research** po democie pragmatics.
4. Web prefetch brał `turn.message` literalnie.
5. Brak critic/rewizji przed wysłaniem.
6. Korekty „chodziło o…” nie były powiązane z biasem intencji.

## 3. Stary pipeline (skrót)

```
POST /chat/turn → ApplicationService → TurnOps
  → memory/psyche brief
  → select_strategy(user_text)   # bez pragmatics
  → freshness guardrail
  → web prefetch(raw message)
  → prompt → provider/tools
  → shape → reflection → write-back
```

## 4. Nowy pipeline

```
POST /chat/turn → ApplicationService → TurnOps
  → memory/psyche brief
  → analyze_pragmatics(raw, history, mem/psyche brief, user/session/turn_id)
  → select_strategy(..., pragmatics=)
       → apply_pragmatics_to_strategy (block instant / force contextual|research / demote false research)
  → _local_non_research_guardrails  # respektuje demot pragmatics + deixis
  → web prefetch(rewritten_query_for_tools)
  → prompt + pragmatics_prompt_block + persona
  → provider/tools
  → shape → critique_response → max 1 revision (tools=[])
  → reflection → write-back (ten sam turn_id)
```

Bez nowego publicznego endpointu. Bez cofania pakietu `aihub/turn/*`.

## 6. Modele danych

Pydantic:

- `IntentCandidate` — label, description, confidence, evidence, requires_context, tool_rewrite, response_mode
- `PragmaticAnalysis` — raw/normalized, speech_act, intents, ambiguity/context scores, sygnały (slang/irony/sarcasm/teasing/sexual…), temporal, needs_* , recommended_strategy, response_mode, conversation_state, rewritten_query_for_tools, critic, correction_learned, timing…
- `ResponseCriticResult` — score 0–100, passed, reason_codes, revision_instruction

## 7. Conversation state

Wykrywane stany: `casual_chat`, `teasing`, `technical_debug`, `planning`, `research`, `correction`, `frustration`, `argument`, `task_execution`, `follow_up`, `meta_request`.

Wpływają na response_mode, strategię, historię/memory/psyche flags i prompt.

## 8. Speech act detection

Hybryda sygnałów: greeting, teasing, sarcasm, complaint, correction, factual_question, task_instruction, meta_request, request…

## 9. Intent candidate ranking

Kandydaci z confidence + evidence; top = primary; bliskie confidence → ambiguity_score ↑ i blokada instant.

## 10. Strategy integration

Twarde reguły w `apply_pragmatics_to_strategy`:

- ambiguity / teasing / sexual / sarcasm / irony / context → **nie instant**
- sports+temporal → **research** + web rewrite
- false research na deixis → **demote do contextual**, web off
- reason codes `PRAGMATICS_*` dorzucane do istniejących

## 11. Memory integration

Ograniczony brief + eventy `user.intent_correction` (session-scoped). Nie zapisuje każdej interpretacji jako trwałej prawdy.

## 12. Correction learning

Scenariusz „Lody robisz?” → „Chodziło o…”:

- `speech_act=correction`
- `record_intent_correction` + `PRAGMATICS_CORRECTION_LEARNED`
- kolejne similar turns: `PRAGMATICS_CORRECTION_BIAS`

**Dowód smoke (signed principal):** correction_learned=true; kolejna zaczepka z biasem seksualnym.

## 13. Psyche / relation

Flaga `needs_psyche` + prompt: dostosuj bezpośredniość/humor/formalność do relation brief; bez udawania człowieka. Persona guard wzmocniony o ripostę na zaczepkę.

## 14. Planner / reasoning

Planner tylko przy `needs_planner`. Reasoning escalation przy wysokiej ambiguity / meta. Prosty tech (`napraw import json`) bez planera.

## 15. Web query rewrite

`raw` zachowany w historii. Tool query z `rewritten_query_for_tools`, np.:

`wynik meczu mistrzostwa świata 2026 mecz data:2026-07-11`  
(bez litery „przed wczoraj”).

## 16. Response critic

Po shape: score/passed/revision_instruction. Przy fail: **1** `_provider_call(tools=[])` — bez ponownego side-effect tools, ten sam turn_id.

Dowody: sarkazm critic 60 + revision; innuendo→prompt obrazkowy critic 35 + revision.

## 25. Znane ograniczenia

1. Hybryda reguł + kontekst; pełny LLM-classifier tylko opcjonalnie przy wysokiej niejednoznaczności — nie jest główną ścieżką.
2. Model nadal bywa „zbyt dosłowny” po korekcie seksualnej (encyklopedia zamiast krótkiej riposty) — critic łagodzi, nie eliminuje 100%.
3. Research sportowy może kończyć się `ok=false` przy braku źródeł (mundial 2026 / braki w web) — rewrite działa, grounding zależy od providera.
4. Riposta na „Lody robisz?” czasem metaforą deserową (nie przepis) — akceptowalne jako teasing, nie jest hardcode’em jednej frazy.
