# 20.07 — Runtime Chat Fix

**Cel:** naprawić autentyczny E2E chat bez nowego subsystemu.  
**Data:** 2026-07-14

---

## 1. Root cause każdego problemu

### A. `json_extract` na PostgreSQL → `agent_handoff_error`
- **Przyczyna:** `GoalEngine._find_similar_open_goal` używał SQLite-owego `json_extract(metadata, '$.goal_fingerprint')`.
- Kolumna `goals.metadata` w PG: **TEXT** (JSON jako string).
- Na agentic path executive buduje kontekst goals → create/find similar → SQL wyjątek → `effective_runtime_path=agent_handoff_error`, `ok=false`, HTTP nadal 200.

### B. HTTP 200 + `ok=false` traktowane jak sukces
- Kontrakt JSON zwraca `ok=false` przy błędzie handoff, ale smoke (`scripts/smoke_chat_real.py`) sprawdzał tylko HTTP status + niepusty tekst.
- Stream SSE (`include_turn_result=false`) nie wysyłał `ok` na evencie `done` → frontend ChatShell kończył stream „sukcesem”.

### C. Banalne pytanie → `agentic` / planner
- Heurystyka `complex_task = n_words>=14 and (" i " in text or commas)` fałszywie odpalała agentic na pytaniach z „i”.
- Cognitive: niska pewność intencji → `force_planner_analysis=True` nawet dla krótkich/meta pytań.
- Po błędzie providera/path: fallback mógł wejść w executive mimo intencji chat.

### D. `memory_hits=38` / śmieci
- `build_context_pack(limit=18, max_chars=6500)` + pełny STM dump (`get_stm` do 20) + brak filtra meta-memory / fallback / sport.
- Trace `memory_hits` liczył wiele warstw (STM+L1+L2+vector+graph+v2) bez globalnego capu.

### E. `user=default` w background
- `AGENT_USER_ID` defaultował do `"default"`; consolidation `AIHUB_CONSOLIDATION_USERS` też `"default"`.
- Systemowy tick mieszał się z przestrzenią użytkownika „default”.

## 3. Poprawione zapytania SQL

**Przed (SQLite-only):**
```sql
AND json_extract(metadata, '$.goal_fingerprint') = ?
```

**Po (dialect adapter):**
- SQLite: `json_extract(metadata, '$.goal_fingerprint') = ?`
- PostgreSQL: `((metadata)::jsonb ->> 'goal_fingerprint') = ?`

Jedyny produkcyjny hot-path z `json_extract` w repozytorium: `goal_engine` (naprawiony). Adapter trzyma SQLite API w jednym miejscu.
