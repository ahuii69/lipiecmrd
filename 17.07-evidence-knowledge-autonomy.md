## 1. Stan przed

Istniał `aihub/knowledge_graph.py` (nodes/edges fact→relation) zasilany z Memory, plus `task_graph.py`, `durable_jobs`, executive/agent. Brakowało: typowanych claims z provenance, evidence scoring, temporal supersession, contradiction engine, bounded graph context w `/chat/turn`, ActionClaimGuard z walidacją, trwałego Execution Graph z recovery/idempotency.

## 2. Root causes

1. KG = słaby graph faktów bez claim_type / evidence_ids / validity.
2. Research/web nie wiązał źródeł z twierdzeniami w turn pipeline.
3. Planner/reasoning słabo korzystał z grafu użytkownika.
4. Deklaracje „naprawione/uruchomione” bez validation evidence.
5. Brak trwałych execution nodes z lease/resume.

## 3–5. Audyt / martwe fragmenty / stary pipeline

| Warstwa | Status | Użycie w chat |
|---------|--------|---------------|
| `knowledge_graph` nodes/edges | **żywy**, legacy | query/planner częściowo; **uzupełniony** mostem WK |
| Memory V2 | żywy | epizody/preferencje — **nie dublowany** |
| `task_graph` | żywy | agent planning |

## 6. Nowy pipeline

```
turn message
 → apply_knowledge_influences_to_decision (retrieve KG context)
 → cognitive pack enrich (claims/entities/stale/disputed)
 → prompt KNOWLEDGE GRAPH layer
 → tools/web …
 → ActionClaimGuard na final response
 → process_turn_knowledge write-back
     entities/claims/evidence/relations/conflicts
     + bridge to legacy knowledge_graph
 → learning (16.07) pozostaje osobno
```

## 7–10. Modele

- `EvidenceRecord` — source_type, scores, excerpt, hash, claim_ids  
- `KnowledgeClaim` — claim_type (fact/opinion/inference/…), status, validity, evidence_ids  
- `KnowledgeEntity` + aliases — scope user, merge audit  
- `KnowledgeRelation` — temporal fields, SPO unique per user  
- `ClaimConflict` — changed_over_time vs direct_negation  

## 11–16. Resolution, provenance, temporal, contradictions, scoring, diversity

- Alias + normalize; **brak fuzzy merge** bez dowodu  
- Merge z `wk_knowledge_events` audit  
- Freshness/primary w `score_evidence`  
- `source_diversity_score` nie premiuje kopii tej samej domeny  
- Temporal supersession przy zmianie wartości (nie myli z negacją)  
- Stale → `verification_required` → optional web / strategy bias  

## 17–19. Memory bridge, Cognitive pack, retrieval

- Memory V2 bez zmian odpowiedzialności  
- CognitiveInfluencePack rozszerzony o `relevant_claims`, `stale_claims`, `disputed_claims`, `verification_required`, `knowledge_reason_codes`  
- Bounded retrieval: seed ≤8, relations ≤40, hops ≤2  

## 20–22. Reasoning / Planner / Execution Graph

- Hints `planner_entity_hints`, relation predicates  
- `ExecutionGraph` + nodes z dependencies, validation, idempotency_key  
- `mark_node_completed` / `fail_node_and_replan` / `resume_execution`  
- Max 2 replans; auth/permanent bez retry  

## 23–26. Validation, ActionClaimGuard, recovery, replanning

- Validation failure → node failed (exit 0 ≠ success)  
- Guard blokuje deklaracje bez tool+validation; zostawia istniejące „nie uruchomi…”  

## 27–28. Goal / Agent

- Execution graph wiąże się z `long_horizon_task_id` / planner_recommended  
- Bez nowego agent worker — reuse durable effects table

## 37. Znane ograniczenia

1. Ekstrakcja entity/claim to reguły + lekkie NLP — nie pełny NER LLM.  
2. Execution Graph nie podłącza automatycznie każdego tool call produkcyjnego (wymaga planner/agentic path).  
3. Legacy `knowledge_graph` nadal parallel (most one-way).  
4. Source lists z research zależą od zawartości trace.
