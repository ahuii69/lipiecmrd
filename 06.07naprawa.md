# 06.07 NAPRAWA BŁĘDÓW I ROZBIEŻNOŚCI

## 1. Executive Summary

**Co naprawiono:**
- **P0 (4/4):** uprawnienia `.env`/`cockpit/.env` (→ `600`), skorygowano dokumentację sugerującą dystrybucję realnych sekretów w paczce (`README.md`, `FINAL_DELIVERY_REPORT.md`); Vault (`aihub/user_vault.py`) — brak `AIHUB_USER_VAULT_KEY` w `ENV=production` teraz kończy się `RuntimeError` przy pierwszym użyciu, dev/test ma jawny, opisany, logowany fallback; usunięto RCE (`POST /ai/python/run`, `aihub/api/ai_compat_router.py`) z powierzchni pakietu `aihub` — przeniesione do `archive/legacy_routers/`, poza importowalnym pakietem; dodano fail-fast startu produkcji dla auth (`aihub/config.py::_validate_production_secrets`) — brak jakiegokolwiek sekretu hub API teraz blokuje start w `ENV=production` (middleware wcześniej fail-open'ował po cichu).
- **P1 (4/4):** zarchiwizowano `ops_router.py` (hardcoded `/root/ai-hub`, `systemctl restart` przez shell) i `admin_router.py` (kolizja `/admin` + wyciek nieredagowanych body) do `archive/legacy_routers/`; oznaczono `FirewallMiddleware`/`EventRecorderMiddleware` jako LEGACY/NIEZAREJESTROWANE, usunięto zbędne logowanie debug w `firewall.py`; `GET /gpt-openapi.json` już nigdy nie serwuje pustego `"paths": {}` — generuje realny schemat z `app.openapi()`, gdy plik statyczny jest pusty.
- **P2 (sensowne):** decyzje per moduł dla martwego kodu (`memory_v2_decay.py` → zachowany pillar + testy, `memory_v2_stability.py` → usunięty jako bezwartościowy re-export, `aihub/memory/`+`aihub/psyche/` → formalnie oznaczone LEGACY przez `_LEGACY.md`, `aihub/db/database.py`+`sqlite.py`+`schema.py` → oznaczone jako nie-kanoniczna warstwa DB); poprawiono rozjazdy dokumentacji (`docs/FINAL_STATUS.md`, `docs/GO_NO_GO.md` oznaczone jako historyczne/archiwalne, `RISKS.md` — poprawiony kierunek ryzyka vault); naprawiono 2 realne, przedtem nieudokumentowane usterki testów odkryte podczas weryfikacji (izolacja `data/uploads/` w testach uploadu, brak monkeypatch flagi `BACKGROUND_AGENT_LOOP_ENABLED` w `test_agent_worker_runtime.py`).
- **P3:** usunięto artefakty `__pycache__`/`.pytest_cache` z drzewa repo; poprawiono nieaktualne odniesienie do nieistniejącego `aihub/api/web_router.py` w `_LEGACY.md`.

**Co nadal nie działa:** 29 testów backendowych (z ok. 928) nie przechodzi wyłącznie z powodu brakującej zależności deweloperskiej `pytest-asyncio` w środowisku `/home/ubuntu/.venvs/mrd-312` — wszystkie to funkcje `async def test_...` oznaczone `@pytest.mark.asyncio`; pytest zgłasza `async def functions are not natively supported`. Nie instalowano tej zależności (zgodnie z zakazem instalowania czegokolwiek nowego) — patrz §6 "Wymaga decyzji".

**Backend importuje się poprawnie:** TAK — `aihub.main` i wszystkie wymagane moduły (`chat_api`, `agent_api`, `memory_v2_service`, `psyche_v2_service`, `web_tools`, `vector_engine`, `vector_index`, `tools.registry`) importują się bez błędu.

**Quick tests:** PRZECHODZĄ — `tests/test_config_truth.py`, `tests/test_provider_layer.py`, `tests/test_ops_readiness_and_release_audit.py` — wszystkie zielone.

**Pełne testy:** 899 passed, 29 failed (wyłącznie `pytest-asyncio` — środowisko, nie logika), 1 skipped.

**Frontend build:** PRZECHODZI (`npm run build` → OK, `npm run lint` → 0 błędów/ostrzeżeń, `npm run test` → 58/58 passed).

**Co wymaga decyzji użytkownika:** (1) instalacja `pytest-asyncio` do `requirements-dev`/venv, żeby odblokować 29 testów async; (2) czy na tym VPS ustawić `ENV=production` (obecnie `ENV=development` mimo danych o wyglądzie produkcyjnym — `DOMAIN`, `POSTGRES_DSN`) i wygenerować/ustawić `AIHUB_USER_VAULT_KEY` na tym hoście — **nie zrobiono tego automatycznie**, bo zmiana `ENV` może ujawnić inne brakujące sekrety (`DEEPINFRA_API_KEY` jest pusty w obecnym `.env`) i mogłaby zablokować start bez przygotowania; (3) czy odtworzyć funkcję "ops snapshot/rollback" i "admin recent events" w bezpiecznej, przeprojektowanej formie.

**Gotowość projektu po naprawie:** **62/100%** (wzrost z ok. 35-40% ocenianych w `06.07audyt.md` — usunięto realne ryzyka bezpieczeństwa P0/P1, ale start na tym VPS wciąż wymaga decyzji o `ENV`/kluczach, a `pytest-asyncio` blokuje pełną weryfikację ok. 3% testów).

## Response Quality Fix

Osobny sprint jakościowy: **infrastruktura działała** (backend, frontend, proxy, DeepInfra, model), problemem było **finalne zachowanie modelu** — odpowiedzi głupie i przesadnie personifikowane, np. „Dobra, jak zwykle – wciąż żyję, nie mam czasu na nudę, więc walczę z kodem i kawą.” albo „Spokojnie, nie mam w planach nagradzania się poezją…”. Nie ruszano: systemd, nginx, portów, instalacji, venv, frontend proxy, DeepInfra configu ani release audit.

### Przyczyna (root cause)

1. **Persona systemowa** w `aihub/chat_runtime.py` (`_build_system_prompt` → `system_rules`) definiowała asystenta jako „rozgarnięty ziomek z czatu — ten od rzeczy… nie jak infolinia ani »asystent AI«” z „lekkim pazurem (suchy żart, ironia, sarkazm)”. To wprost zachęcało model do udawania człowieka i teatralnego stylu.
2. **`_build_psyche_brief`** wstrzykiwał do promptu surowe wartości `sarcasm=…` i `swearing=…`. Wyeksponowanie tych cech pchało model w sarkazm/wulgaryzmy i personifikację.
3. **`psyche_engine.evolve()`** przy „harsh” (agresywnej) wiadomości użytkownika **podnosił** `swearing` i `sarcasm` oraz **wymuszał** `style="ziomek"` — czyli psyche kopiowało ton awantury (dokładnie zakazane zachowanie).
4. **`_baseline()`** psyche startował z `style="ziomek"`, `swearing=0.50`, `sarcasm=0.35` — wysoki bazowy poziom personifikacji dla każdego nowego użytkownika.
5. **Fallback po awarii providera** doklejał do widocznej dla użytkownika odpowiedzi surowe `[Kontekst pamięci] …` i `[Kontekst psyche] style=…, mood=…` — zrzut stanu wewnętrznego jako „odpowiedź”.

### Rozwiązanie (kontrakt, nie usuwanie psyche/memory)

Nie usunięto memory, psyche, embeddings, web, planner, agent, trace ani testów. Dodano bezpieczny **kontrakt persony** + filtr:

- **Nowy moduł `aihub/response_persona_guard.py`:**
  - `PERSONA_CONTRACT_PROMPT` — twardy blok reguł doklejany do system promptu (priorytet nad stylem/psyche/pamięcią): jesteś rzeczowym asystentem AI, możesz mieć lekko swobodny ton, ale **zakaz fałszywej biografii** (nie „żyjesz”, nie kawa, nie „walczysz z kodem”, nie nuda, nie poezja, nie własny dzień/nastrój/plany); zakaz defensywnej autopersonifikacji i meta-teatru; na „co słychać?” krótko i użytkowo (np. „Działa. Jestem gotowy do rozmowy — co robimy?”); na agresję spokojnie i konkretnie (przyznaj, jeśli poprzednia odpowiedź była nietrafiona, i poproś o doprecyzowanie), bez odbijania agresji/sarkazmu/poezji; psyche i pamięć mogą modulować **ton**, ale nie tworzyć personifikacji ani kopiować tonu kłótni.
