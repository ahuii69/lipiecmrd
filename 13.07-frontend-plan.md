# 13.07 — Plan migracji frontendu czatu (audyt przed implementacją)

Data: 13.07.2026  
Zakres: główny chat (`app/page.tsx`) + warstwa persony odpowiedzi AI  
Bez zmian: endpointów, payloadów, auth, streamingu, pamięci backendowej, upload/STT API.

---

## 1. Aktualny przepływ danych

### Auth / tożsamość
1. Użytkownik wchodzi na `/` → middleware przekierowuje na `/login` jeśli brak sesji.
2. `LoginForm` / `RegisterForm` → `POST /api/aihub/auth/login|register` (BFF proxy).
3. Cookie sesji; przy wejściu na `/` → `useAuthPrincipal()` → `GET /api/aihub/auth/me`.
4. `principal.user_id` → `cockpitStore.bindAuthPrincipal(userId)` — jedyne źródło `authUserId`.
5. **Nie wolno** generować losowych `u_*` w localStorage.

### Sesje
1. `cockpitStore.sessions` — persist localStorage (`aihub-cockpit-v7`).
2. Przy mount `AiOsShell`: `apiClient.getSessions(userId)` → `mergeServerSessions`.
3. `createSession()` — lokalnie + aktywacja.
4. `setActiveSession(id)` — przełączenie wątku.

### Historia
1. `useSessionHistoryFromServer({ sessionId, userId })` → `GET /chat/session/{id}/history`.
2. `replaceSessionMessagesFromServer` — backend nadpisuje transkrypt (fail-soft przy błędzie sieci).
3. Po turze: `reloadSessionHistoryFromServer` w `onDone` streamu.

### Wysyłanie / streaming
1. `streamChatTurn(payload, signal, handlers)` → `POST /chat/turn?stream=true` (SSE).
2. Handlery: `onDelta`, `onReplace`, `onStatus`, `onTool`, `onMemory`, `onDone`.
3. Store: `appendMessage` (user + assistant placeholder), `appendMessageContent`, `patchMessage`.
4. Retry: `truncateSessionMessagesTail` + ponowne wysłanie z `retry: true`.

### Upload / STT
1. Upload: `uploadChatFile({ user_id, session_id, file })` → draft w stanie lokalnym.
2. Send: `attached_file_ids` w payloadzie `/chat/turn`.
3. STT: `transcribeChatAudio(blob)` → tekst w composerze → `input_via_stt: true`.

### Pamięć / źródła (UI)
1. Drawer: `getMemoryV2Summary`, `getMemoryContextPack` (istniejące API).
2. Źródła: `contextChips` z SSE `done` na wiadomości asystenta.

### Błędy
1. `formatChatTurnErrorMessage` / `formatUserFacingError` w `hub-auth-errors.ts`.
2. Mapowanie 401/403/502/503/network — wymaga doprecyzowania copy wg spec §6.
