## 2. Co było częściowo wpięte (i zostało domknięte)

- **Memory / Memory V2** — retrieval i prompt były; teraz też reason-codes (`COG_MEMORY_*`), contradiction → force reasoning, critic underuse.
- **Psyche / Psyche V2** — style w prompt; teraz length/humour/friction directives + confidence delta (`COG_PSYCHE_*`).
- **Planner** — flags `planner_recommended` / escalation; teraz wymuszane przez low intent confidence, goals urgency, correction, conversation plan.
- **Pragmatics** — już realny wpływ; cognitive pakuje ranking intentów z candidate_intents.
- **Strategy selector** — nadal kanoniczny wybór; cognitive **mutuje** decision_core po selekcji (bez zmiany publicznego API).

## 6. Miejsca, gdzie AI realnie zmienia zachowanie

1. Niska pewność intencji / wysoka ambiguity → force reasoning/planner (+ ewentualnie `instant`→`contextual`).
2. Psyche verbosity / User Model length → dyrektywy + hard trim odpowiedzi za długich.
3. Goals z wysokim urgency + długa wiadomość → planner + tool order memory→planner→research.
4. Experience fail/miss → spadek confidence, blokada `instant`, tool order research-first.
5. Correction hints → binding stylu + planner bias + confidence down.
6. Research: ranked queries; przy braku wyniku próbuje następny wariant.
7. Critic: helpdesk/filler/length/fake-web → jedna regeneracja bez side-effect tools.
8. Po 300 turach Conversation State nadal trzyma primary_topic / decided / rejected / plan / executed (test).
9. „napisz krócej” uczy User Model `preferred_answer_length=short` i utrwala w event_log.

## 10. Remaining technical debt

1. Provider balance / multi-provider failover w produkcji (poza zakresem API).
2. Conversation State oparty o event_log — przy bardzo długim historii warto zmaterializować do dedykowanej tabeli (bez zmiany API).
3. Scoring research jest heurystyczny (nie LLM-ranker) — działa, ale może być uczony z calibration signals.
4. Softening: eskalacja nie zawsze zmienia `instant` gdy ambiguity < 0.55 (świadomie, by nie psuć greeting/tech); można dociągnąć osobnym policy knob.
5. Executive handoff path — cognitive codes są w decision_core; warto w przyszłości zmergerować pełny `cognitive_trace_fields` także w pure handoff-before-provider (gdy nie ma chat LLM loop).
