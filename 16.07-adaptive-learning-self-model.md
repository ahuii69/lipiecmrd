## 1. Stan przed

Po 15.07 system miał cognitive integration, User Model, Conversation State i częściowe write-backi (experience bias, corrections, calibrate). Brakowało kanonicznego outcome, delayed feedback z resolucją targetu, lekcji z **wykonywalnym** `machine_action`, failure/success memory z konsumentem, self-modelu runtime, long-horizon rejected-guard oraz ścieżki replay bez side-effects.

## 2. Root causes (luk domkniętych w tej iteracji)

1. Lekcje były tekstowe → brak gwarantowanego konsumenta → **dodano `machine_action` + `apply_machine_actions`**.
2. Delayed feedback słabo rankingował „pierwszy sposób” → **resolver z deixis / recency / overlap / LHT**.
3. Brak trwałego storage delayed feedback → **tabela `delayed_feedback`**.
4. Schema ensure na Postgres psuło transakcję przez `PRAGMA` → learning `LEARN_DEGRADED` w produkcji → **naprawione (information_schema + rollback)**.
5. Rejected decisions nie były twardo chronione po wielu turach → **guard + test 20 tur**.

## 6–7. Stary vs nowy learning pipeline

```
PRE-DECISION:
  load self-model, lessons, failures, successes, UM v2, LHT
  → apply_learning_influences_to_decision (+ machine_actions)
  → prompt ADAPTIVE LEARNING layer

POST-TURN:
  detect delayed feedback → resolve target turn_id → update outcome + persist
  evaluate TurnOutcomeEvaluation (składowe, nie jeden bool)
  attribute_causes (observed / strongly_inferred / weakly_inferred / unknown)
  extract lessons with machine_action → upsert (dedup/reinforce/contradict/decay)
  bump metrics → self-model → UM v2 → failure/success → LHT
  → learning_trace_fields → trace
```

## 10. TurnOutcomeEvaluation

Składowe m.in.: intent/style/grounding/verbosity/tool/research/latency + sygnały acceptance/rejection/correction + `overall_reward` jako funkcja składowych (nie losowy bool). Pola rozszerzone (`request_id`, `correlation_id`, `memory_usefulness_score`, flagi detected, …) — część w modelu + metadata.

## 11. Delayed feedback

Detection → ranking targetów (recency, token overlap, „pierwszy/tamten”, LHT tokens) → `DelayedFeedbackEvent` → update outcome + wiersz w `delayed_feedback`.

**Runtime smoke:**  
`turn A = 17502088-…` → po dygresji → „ten pierwszy sposób zadziałał, dokładnie” → `delayed_feedback_target_turn_id = 17502088-…` (**match**).

## 12. Causal attribution

Typy: `observed | strongly_inferred | weakly_inferred | unknown`. Nie udaje pewności przy jednym słabym sygnale (`unknown` gdy brak dowodów).

## 13–16. Lesson Engine / reinforcement / contradictions / decay

- Dedup po `content_hash + scope + user_id`
- Reinforcement ↑ confidence / evidence
- Contradiction ↓ confidence / suppress
- Decay + `expires_at` → archive/suppress
- **Wymagane `machine_action`** (słabe lekcje bez akcji odrzucane)
- Consumer: `aihub/adaptive_learning/actions.py` → realna zmiana `selected_strategy`, verbosity, planner, tools, provider/research hints

## 17–18. Failure / Success Memory

Zapis przy negatywnym/pozytywnym outcome; odczyt w `apply_learning_influences_to_decision` (`LEARN_FAILURE_MEMORY_USED` / success codes).

## 19–20. Self-model + confidence calibration

Wersjonowany self-model (strategy/planner/research success, weak/strong domains). Kalibracja z beta-smoothing; mała próbka → pull do prior (`prior_low_n` / blend do 0.5).

## 21–25. Strategy / planner / tool / provider / research learning

Metryki bumpowane per turę; tool order z success rate; provider preference z history; research_metrics z query hash (bez pełnej treści stron). Twarde guardy: nie demotować research→instant gdy web required.

## 26. User Model V2

Cechy z evidence/confidence/decay; wpływ na `learning_length_directive` + prompt layer.

## 27–28. Long-horizon + rejected decision guard

TaskState aktywny przez dygresje; rejected decisions w task + prompt „NIE proponuj ponownie”.  
**Test:** po **20** turach szumu `LEARN_LHT_REJECTED_GUARD` + `LEARN_REJECTED_OPTION_SUPPRESSED` przy wzmiance o odrzuconej opcji.

## 29–30. Reflection V2 (kandydaci) + anti-drift

Pipeline po turze generuje kandydatów (outcome/causal/lesson/failure/success/self/UM/LHT); walidacja confidence, dedup, contradiction, scope, decay.  
Anti-drift: bounded bias (`_MAX_BIAS_DELTA_PER_TURN`), min samples, global threshold wyższy, per-user isolation, confidence caps.

## 31. Replay

`scripts/replay_turns.py` + `aihub/adaptive_learning/replay.py`: offline evaluation, bez side-effects, bez write-backów production, decision diff JSON/MD.

## 32. Observability

Trace: `outcome_*`, `delayed_feedback_*`, `lessons_*`, `causal_attribution_count`, `raw/calibrated_confidence`, `learning_reason_codes`, `LEARN_*` reason codes (machine actions, LHT, failure memory). Bez promptów/sekretów/pełnych payloadów.

## 39. Znane ograniczenia

1. Publiczny response `/chat/turn` nie zawsze zwraca `session_id` w root JSON — klient musi podawać `session_id` (smoke używa stałego).  
2. Provider produkcyjny może być zdegradowany (billing) — nie mylić z regresją learningu.  
3. `memory_v2_lessons` legacy nadal istnieją obok AL (bez usuwania).  
4. Reflection nie jest osobnym workerem — kandydaci powstają w `process_turn_learning`.  
5. Transient timeout vs trwała awaria providera: timeout_sum w metrykach, ale score nie jest hard-ban bez próbki.
