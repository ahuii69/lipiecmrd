## 9. Audyt frontend-backend

- **Framework:** Next.js 15.5.14 (App Router), React 19.0.0 — potwierdzone `cockpit/package.json:34-36` i strukturą `cockpit/app/`.
- **API client:** `cockpit/lib/api/client.ts` (732 linie) — jeden scentralizowany obiekt `apiClient` z ~40 metodami, wszystkie przechodzące przez `hubJson`/`hubRequest` → `buildAihubProxyUrl` → `/api/aihub/<path>`. **Zero direct fetch do backendu z komponentów** — zweryfikowano brakiem innych wzorców `fetch(` do `AIHUB_BASE_URL` poza `client.ts` i samym proxy route.
- **Proxy (BFF):** `cockpit/app/api/aihub/[...path]/route.ts` (229 linii) — jeden uniwersalny handler dla GET/POST/PUT/PATCH/DELETE, przekazujący do `AIHUB_BASE_URL` (domyślnie `http://127.0.0.1:8080`). Waliduje każde żądanie przez `isCockpitProxyAllowed(method, logicalPath)` z `cockpit-proxy-gate.ts` **przed** wysłaniem do backendu — żądania niepasujące do `cockpit-proxy-allowlist.json` (55 wpisów) dostają `403` z kodem `cockpit_proxy_forbidden`. Usuwa nagłówki hop-by-hop i **jawnie usuwa** przychodzące `x-api-key`/`authorization`/`x-aihub-proxy-token` od klienta przed nadpisaniem własnymi, wyliczonymi server-side (`buildForwardHeaders:60-62`).
- **Konfiguracja środowiska:** `cockpit/.env` + `cockpit/.env.example` + fallback do root `.env` przez `next.config.mjs::mergeParentEnvIfMissing()` (blocklist `PORT`/`HOST`/`WORKERS`, żeby Next nie próbował wstać na porcie backendu). Alias nazw kluczy hub współdzielony przez `config/hub_key_env_names.json` (czytany zarówno przez `aihub/auth_patch.py` w Pythonie, jak i `cockpit/lib/api/resolve-hub-api-key.ts` w TS) — **dobra praktyka single-source-of-truth**.
- **Zgodność endpointów:** wszystkie 40 metod `apiClient` wołają ścieżki obecne w `cockpit-proxy-allowlist.json` (55 wpisów) — zweryfikowano manualnie po nazwach ścieżek; **zero wykrytych rozjazdów**. Dla plików **krytycznych dla runtime, bezpieczeństwa lub kontraktu API/UI** poniżej podano pełny szablon (Typ/Status/Rola/Użycie/Importy/Eksporty/Testy/Problemy/Dowody/Priorytet/Rekomendacja). Dla dużych, jednorodnych grup plików (pozostałe silniki `aihub/*_engine.py`, pozostałe testy `tests/test_*.py`, pozostałe panele `cockpit/features/**`, pozostałe skrypty `scripts/**`) zastosowano **zwięzłe tabele per katalog** z kolumnami Status/Dowód/Priorytet — każdy plik ma wiersz. Ocena statusu dla grup opartа jest na: (a) wyniku `py_compile` (0 błędów na wszystkich), (b) grepie referencji importu (§5, §13), (c) obecności w `canonical_http_surface.py` / `include_router` (§8), (d) obecności odpowiadającego pliku testowego po nazwie.

## 17. Finalny werdykt

**Realny stan projektu:** to nie jest prototyp. Skala testów (533 funkcje testowe), głębokość kontraktów (Pydantic modele, manifest HTTP z automatyczną walidacją, allowlist BFF zsynchronizowana skryptem), oraz jakość samodokumentowania kodu (`ACTIVE_CONFIRMED`/`LEGACY`/`SPLIT_BRAIN` markery) wskazują na projekt w fazie **zaawansowanej bety / pre-produkcji ("release candidate" z zastrzeżeniami)**. Dokumenty w repo (`FINAL_DELIVERY_REPORT.md`, `COMMERCIAL.md`, `LICENSE` z All Rights Reserved) wskazują, że projekt jest przygotowywany do sprzedaży/wdrożenia komercyjnego, nie jest to open source hobby-project.

**Co odpali się dzisiaj (w tym konkretnym sandboxie):** nic z warstwy runtime — ani backend (brak `pip`/zależności), ani frontend (brak `node`/`npm`), ani żadna zewnętrzna usługa (Postgres/Ollama zamknięte porty). **Odpalają się** wyłącznie: sama walidacja składniowa Python (`py_compile` — 100% czysty wynik) oraz odczyt/analiza statyczna wszystkich plików tekstowych.

**Co nie odpali się dzisiaj:** cały stack HTTP (backend + frontend), wszystkie testy (`pytest`, `vitest`, `playwright`), wszystkie skrypty smoke/diagnostyczne wymagające zależności lub sieci.

**Co jest pierwsze do naprawy (w kolejności):**
1. Rotacja i usunięcie realnych sekretów z plików `.env`/`cockpit/.env` w tym stanie repo (P0).
2. Ustawienie i wymuszenie `AIHUB_USER_VAULT_KEY` przed jakimkolwiek użyciem produkcyjnym funkcji Vault (P0).
3. Usunięcie lub formalna archiwizacja `aihub/api/ai_compat_router.py` (RCE) i `aihub/api/ops_router.py` (`systemctl restart`) — nawet jako kod nieaktywny, stanowią dług architektoniczny wysokiego ryzyka (P0/P1).
4. Na docelowym hoście: instalacja zależności (`pip install -r requirements.txt`, `npm install`), uruchomienie Postgres, weryfikacja `./doctor.sh --profile prod` — dopiero to pozwoli faktycznie zweryfikować runtime, którego ten audyt nie mógł zweryfikować z powodu ograniczeń sandboxu.

**Czego nie wolno wycinać:** kanonicznej warstwy HTTP (`aihub/main.py` + 9 zamontowanych routerów `*_api.py`) — jest w 100% zweryfikowana i zgodna z frontendem. Warstwy testów (533 funkcje) — to główny mechanizm ochrony przed regresją w projekcie tej skali. Mechanizmu `canonical_http_surface.py` — jedyny w repo automatyczny strażnik przed driftem API. `aihub/api/_LEGACY.md` — najbardziej precyzyjny, aktualny dokument audytowy w repo; powinien być traktowany jako wzór dla resztek dokumentacji.

**Czego nie wolno przepisywać bez planu:** `aihub/chat_runtime.py` (6389 linii) — zbyt duży, żeby bezpiecznie refaktoryzować bez dedykowanego planu podziału i pełnego przebiegu 533 testów jako safety net. Warstwy DB (`db/runtime.py` 2321 linii + równoległy `db/database.py`/`db/sqlite.py`/`db/schema.py`) — konsolidacja tych dwóch gałęzi schematu wymaga jasnej decyzji, która wygrywa, bo mylące importy (`aihub.db` vs `aihub.db.database`) mogą prowadzić do cichej niezgodności danych.

**Jaki powinien być następny sprint naprawczy:**
1. **Sprint bezpieczeństwa (1 tydzień):** rotacja sekretów, klucz Vault, usunięcie/archiwizacja dormant RCE i ops-restart, audyt fail-open w `auth_patch.py`.
2. **Sprint środowiska (równolegle, poza tym repo):** na docelowym hoście z Node.js + pip zainstalować zależności i faktycznie zweryfikować `./doctor.sh --profile prod`, `pytest -q`, `npm run build`/`test` — to jedyny sposób, żeby przejść od "działa statycznie" do "działa realnie", co ten audyt sandboxowy nie mógł potwierdzić.
3. **Sprint porządkowy (P2/P3, po sprincie bezpieczeństwa):** konsolidacja duplikatów DB, usunięcie/archiwizacja martwych pakietów `aihub/memory/`, `aihub/psyche/`, `memory_v2_decay.py`, `memory_v2_stability.py`, aktualizacja `docs/FINAL_STATUS.md`/`GO_NO_GO.md` jako "archived", uzupełnienie `tests_hint` dla ~25 tras bez pokrycia w manifeście.
