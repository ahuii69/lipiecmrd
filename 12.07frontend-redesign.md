# Frontend redesign — strona logowania AI-Hub (12.07)

## Rzeczywista przyczyna surowego HTML / czarnego ekranu

**HTML i CSS były poprawne po stronie serwera**, ale przeglądarka **nie stosowała stylesheetu** przy dostępie przez HTTP (np. `http://51.38.133.0:3001/login`).

### Root cause

CSP zawierało **`upgrade-insecure-requests`**, podczas gdy frontend **nie obsługuje TLS** na porcie 3001 (tylko plain HTTP).

Efekt w przeglądarce:

1. Dokument ładuje się po **HTTP**
2. CSP wymusza upgrade assetów do **HTTPS**
3. `https://51.38.133.0:3001/_next/static/css/*.css` kończy się błędem TLS (`wrong version number` — brak certyfikatu)
4. **CSS nie jest stosowany** → domyślna czcionka serif, białe/czarne tło bez layoutu, surowe inputy/buttony
5. Przy ciemnym tle i domyślnym `color: black` widać **czarny ekran z scrollbarem** (treść SSR obecna, ale niewidoczna)

Na `127.0.0.1` problem był ukryty — Chrome często **wyłącza upgrade-insecure-requests dla localhost**, więc CSS ładował się po HTTP i strona wyglądała poprawnie.

### Dowód z finalnego CSS (po naprawie)

Plik: `.next/static/css/b124314790a893d4.css` (~50 KB)

Zawiera m.in.:

- `.bg-neutral-950`
- `.font-sans` (+ `@font-face` Inter)
- `.min-h-\[100dvh\]`
- `.login-animate-page`
- `.rounded-\[1\.75rem\]`
- `.backdrop-blur-xl`
- `.h-12`

Runtime po naprawie (`http://51.38.133.0:3001/login`):

- CSP **bez** `upgrade-insecure-requests`
- `<link rel="stylesheet" href="/_next/static/css/b124314790a893d4.css">` → **200**
- computed: `bodyBg: rgb(10, 10, 10)`, `bodyFont: Inter`, `loginBg: rgb(10, 10, 10)`, `loginColor: rgb(245, 245, 245)`
- 710 reguł CSS aktywnych w przeglądarce

## Naprawa

| Zmiana | Plik |
|--------|------|
| `upgrade-insecure-requests` tylko opt-in (`AIHUB_CSP_UPGRADE_INSECURE=1`) | `cockpit/middleware.ts` |
| Fallback `opacity: 1` na animacjach loginu (gdy CSS opóźniony) | `cockpit/styles/globals.css` |
| Jawny scan `./styles/**/*` w Tailwind content | `cockpit/tailwind.config.ts` |
| Poprawka ścieżki CSS w shadcn config | `cockpit/components.json` |
| Test regresyjny login + CSS + brak upgrade-insecure | `cockpit/tests/login-tailwind-runtime.test.ts` |
| Asercja braku upgrade-insecure w CSP | `cockpit/tests/middleware-headers.test.ts` |

**Auth, BFF, backend, cookies, session flow, signed principal — bez zmian.**

Gdy frontend stoi za reverse proxy z TLS, ustaw `AIHUB_CSP_UPGRADE_INSECURE=1` w env.
